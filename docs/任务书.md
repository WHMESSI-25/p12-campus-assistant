## 一、目标

把 P6 的校园办事 RAG 从「能演示」升级为「同学真的会用、能收集反馈、能迭代」的小产品。

**产品目标**

- 面向汕大在校学生，提供单轮校园办事问答；
- 回答带原文出处；资料不足时明确拒答，不编造；
- 对「怎么办」类问题，额外生成一张结构化**办事清单**：步骤、材料、地点、时限、注意事项；
- 手机和电脑都能直接打开使用，不需要登录。

**验收目标**

- ≥ 5 个真实用户，每人至少 3 次真实提问；
- 收集 ≥ 5 条有效反馈（有用/没用 + 可选文字）；
- 完成 ≥ 1 轮按反馈落地的迭代，并有 commit 记录；
- 有可公开访问的 URL、GitHub 仓库、README、`RETROSPECTIVE.md`。

**交付物**

1. 可访问的产品 URL；
2. 新项目 GitHub 公开仓库；
3. 产品 README（架构、数据流、运行/部署、token 预算）；
4. 反馈记录与迭代记录；
5. 300 字以上复盘 `RETROSPECTIVE.md`。

## 三、范围

### P0：必须做（MVP）

1. **单轮问答**：输入问题 → 检索 → 生成带出处回答；
2. **办事清单卡片**：对流程类问题生成「步骤 / 材料 / 地点 / 时限 / 注意事项」，字段缺失就留空，不编造；
3. **拒答**：知识库无相关内容时明确说明，并给出咨询方向；
4. **出处展示**：每条回答下方列出实际引用的资料标题与原文链接；
5. **快捷问题**：首屏放 4–6 个真实高频问题；
6. **反馈**：每条回答下「有用 / 没用」，可选填一句原因；
7. **限额**：匿名会话级频率限制 + 全局预算熔断；
8. **移动端适配**：手机浏览器可用，输入框不被键盘遮挡；
9. **部署上线**：公开 URL。

### P1：有余力再做

- 本地历史记录（`localStorage`，不上传服务器）；
- 热门问题统计；
- 回答复制/分享；
- 简单的使用说明页。

### 明确不做

- 不做注册/登录/用户中心；
- 不做多轮对话记忆（MVP 保持单轮，降低复杂度和 token）；
- 不重新爬取新语料（复用 P6 的 112 篇）；
- 不做管理后台（反馈先落 JSONL 文件，够用）；
- 不做原生 App。

## 四、约束

### 技术

- Python 3.12；Web 框架优先复用 FastAPI；
- 向量检索与 BM25 在服务端完成，模型本地加载；
- 模型默认 `deepseek-chat`（非思考模式，避免 reasoning token 浪费）；如接口变更，回退 `deepseek-flash` 并关闭思考；
- 所有代码、数据、日志只放 D 盘；
- 注释、commit message、文档全中文。

### 成本（总预算 ¥2）

- 单次回答输出上限 **700 tokens**；
- 单次问答目标成本 **≤ ¥0.03**；
- 每日预算上限 **¥0.80**，达到即停止调用并返回友好提示；
- **总预算上限 ¥2.00**，账本持久化，重启不丢；
- 相同问题 24 小时内命中缓存，不重复调用模型；
- 拒答路径不调用模型，不产生 token；
- 开发期不反复跑 40 题 LLM 评分；用 **10 题核心集** 做人工/规则验收，最终只在预算允许时跑一次完整回归。

### 安全

- `LLM_API_KEY` 只从环境变量读取，绝不写入代码、前端、日志或仓库；
- 前端不接触 DeepSeek Key，所有模型调用走服务端代理；
- 对用户输入限长（1–200 字），做基础注入防护；
- 不记录用户敏感个人信息；反馈日志只存问题、回答摘要、评分、时间；
- 上线前检查 `.gitignore`，确保 `.env`、日志、密钥不入库。

### 体验

- 首屏必须让用户 5 秒内知道「这是什么、能问什么」；
- 回答中的关键数字、时限、材料必须逐字来自资料；
- 出错时给人话提示，不抛 Python 异常；
- 手机端优先，桌面端不塌。
